ℹ️
The problem in one sentence After the auto-calculation feature, setTreeItems() updates the internal _studyItems map with fresh calculation results, but _selectedItem remains a pointer to the pre-calculation object — so the Report tab, sync-status banner, and geometry plot all display stale outputs until the user clicks away and back.
✅
The fix in one sentence After each _studyItems mutation, re-point _selectedItem to _studyItems[_selectedItem.index] — one assignment, before notifyStateChange() fires, so every subscriber sees fresh data in the same render cycle.

1 Root Cause

⚠️
State management invariant violation StudyTreeDataProvider maintains two private fields that must always refer to the same version of the selected item: _studyItems[selectedIndex] and _selectedItem. Three mutation paths break this invariant.
Method Updates _studyItems Syncs _selectedItem Called by User-visible bug
setTreeItems() ✓ Yes ✗ No — bug Auto-calc (4×), RunHAC (4×), study load/close/new/save Report tab shows stale outputs after calculation
updateTreeItem() ✓ Yes ✗ No — bug Public API — currently unused externally Latent; no current caller exposes this
onRenameItem() ✓ Yes ✗ No — bug Tree right-click rename Right-panel header shows old name after rename
saveFormData() ✓ Yes ✓ Yes (lines 1241 & 1271) Form autosave None — already correct
setSelectedItem() – ✓ Yes (explicit assignment) Tree item click / navigation None — this is the workaround users hit today
🔍
Why navigation "fixes" it Clicking a different tree item calls onSelectItems() → setSelectedItem(newItem) → _selectedItem = newItem where newItem is read from the (now-fresh) _studyItems. Clicking back to the original item repeats this with the fully calculated item. Navigation is an accidental fix for the sync bug, not intended behaviour.

3 Architecture & Data Flow

Current (broken) flow — after auto-calc writes results

useAutoCalculation │ ├── fetch("/api/bs-calculation/batch") → results │ └── provider.setTreeItems(updatedStudyItems) │ ├── _studyItems ← merged with fresh outputs ✓ │ ├── _selectedItem ← UNCHANGED (stale pointer) ✗ │ └── notifyStateChange() │ └── forceUpdate({}) in layout.tsx │ └── context re-render │ ├── ScenarioHacReport reads dataProvider.selectedItem │ → stale _selectedItem.outputs ✗ │ └── SyncStatusBanner reads item.calculationState → stale "out-of-sync" status ✗

Fixed flow — after this change

useAutoCalculation │ ├── fetch("/api/bs-calculation/batch") → results │ └── provider.setTreeItems(updatedStudyItems) │ ├── _studyItems ← merged with fresh outputs ✓ │ ├── _selectedItem ← = _studyItems[_selectedItem.index] ?? _selectedItem ✓ │ └── notifyStateChange() │ └── forceUpdate({}) in layout.tsx │ └── context re-render │ ├── ScenarioHacReport reads dataProvider.selectedItem │ → fresh outputs displayed immediately ✓ │ └── SyncStatusBanner reads item.calculationState → "calculating" / "in-sync" / "failed" ✓

Key invariant restored

At all times: _selectedItem === _studyItems[_selectedItem.index]
(except during the brief window between _studyItems assignment and the sync line — now eliminated by placing the sync immediately after).

5 Before / After Code

setTreeItems() — lines 604–610

✗ BEFORE
public setTreeItems(items: StudyItems): void {
  this._studyItems = this.updateStudyItems(items);
  this.onDidChangeTreeDataEmitter.emit(
    Object.keys(this._studyItems) as TreeItemIndex[]
  );
  this.notifyStateChange();
}
✓ AFTER
public setTreeItems(items: StudyItems): void {
  this._studyItems = this.updateStudyItems(items);
  this._selectedItem =
    this._studyItems[this._selectedItem.index]
    ?? this._selectedItem;
  this.onDidChangeTreeDataEmitter.emit(
    Object.keys(this._studyItems) as TreeItemIndex[]
  );
  this.notifyStateChange();
}

updateTreeItem() — lines 612–618

✗ BEFORE
public updateTreeItem(item: StudyItem): void {
  this._studyItems = this.updateStudyItems({
    [item.index]: item,
  });
  this.onDidChangeTreeDataEmitter.emit([item.index]);
  this.notifyStateChange();
}
✓ AFTER
public updateTreeItem(item: StudyItem): void {
  this._studyItems = this.updateStudyItems({
    [item.index]: item,
  });
  if (this._selectedItem.index === item.index) {
    this._selectedItem = this._studyItems[item.index]!;
  }
  this.onDidChangeTreeDataEmitter.emit([item.index]);
  this.notifyStateChange();
}
