HacStatusIndicator — Move Inline with Study Name

Relocate the HAC calculation status indicator from a toolbar spacer to sit inline beside the study name <h1>, dropping all button chrome and gaining a contextually meaningful home.

📁 Branch feat/auto-hac-calculation
🗂️ Files changed 3 (2 edit · 1 new)
🧪 Tests New test file, 9 cases
⚡ Risk Low

01 Executive Summary

HacStatusIndicator currently occupies the sidebar toolbar as a flex-1 spacer between Save and Export. This placement is accidental — the component carries study-level calculation status, not an action, yet it is styled as an outline <Button> and fills leftover space. 90% of the time it is non-interactive (cursor-default, pointer-events-none), so it looks like a button that does nothing.

The fix moves the indicator to sit flush-right of the study name <h1>. This ties the status directly to the study entity (the thing being calculated), follows the pattern used by GitHub CI badges next to PR titles and Figma sync indicators next to filenames, and allows the component to shed its button chrome entirely — no border, no background — gaining a subtle hover ring only in the single state where it is clickable (failed).

Alongside the relocation, the toolbar gains a proper flex-1 spacer to keep the file actions (File / Save) left-grouped and export/settings right-grouped. Icons are upscaled from h-4 w-4 to h-5 w-5 to match the text-xl heading.

No-study-loaded state

Confirmed behaviour: When no study is loaded (isStudyLoaded === false), the title row does not render at all — the indicator disappears with it. The toolbar still renders normally with the spacer. This is intentional; the disabled state (faint icon, tooltip "No study loaded") is no longer needed since the context (title row) itself disappears.

06 Risks & Edge Cases

Risk / Edge CaseLevelMitigation
Badge overflow clipping
The failed-state badge uses absolute -right-2 -top-2. Without the button's outer padding, the badge could be clipped by a parent with overflow-hidden.		 LOW The new title row wrapper uses default overflow-visible. The <h1> has truncate but that applies text overflow, not box overflow. Verify visually after implementation.
Tooltip on non-focusable span
Radix TooltipTrigger asChild on a non-focusable element means keyboard users lose tooltip access for inert states.		 LOW Mitigated by adding tabIndex={0} to the <span> wrapper, making it keyboard-focusable. Current Button already removes keyboard access for non-clickable states (tabIndex={-1}), so this is actually an improvement.
Toolbar layout with no authenticated user
When canUseFileActions=false (unauthenticated), the left side of the toolbar is empty. The flex-1 spacer alone with Export/Settings on the right is the intended layout.		 LOW The spacer pushes Export/Settings right — same visual as the current HacStatus flex-1 behaviour. No change needed.
Icon size change affects badge position
Changing h-4 w-4 → h-5 w-5 on the XCircle icon shifts the badge attachment point slightly.		 LOW The badge uses -right-2 -top-2 absolute offsets which are relative to the containing relative inline-flex span, not the icon itself. The protrusion is cosmetic. Verify badge remains visible and doesn't overlap text.
Study name truncation with icon present
Adding a shrink-0 icon to the title flex row reduces space available for the study name.		 LOW flex-1 on the <h1> ensures it takes remaining space and truncates correctly. The icon is h-5 w-5 + p-0.5 ≈ 24px, minimal footprint.
isDisabled state still in component internals
After move, isDisabled is never true at the new call site (title row is guarded by isStudyLoaded). Dead code path.		 LOW Kept deliberately for defensive self-containment and test coverage. The disabled state is tested in the new test file. Not removed.
CalculationFailureModal DOM nesting
Modal now lives inside the title row flex container in the DOM.		 LOW Radix Dialog portals to document.body. DOM nesting has zero effect on rendering, z-index, or focus management.

Tasks A and B land in a single atomic commit. The refactored component and its tests should be committed together so the commit is self-verifying (tests pass against the new markup immediately).
