Implementation Plan

Strip Auto-HAC Calculation to Bare Essentials

The feat/auto-hac-calculation branch grew well beyond a debounced auto-calculation hook: a dedicated status indicator, a failure modal with breadcrumbs and error sanitization, root-cause filtering, retry-all, and cross-component "jump to HAC tab" plumbing. This plan reduces the branch to its essentials — keep the debounced auto-calculation hook and replace the dedicated indicator/modal with a single minimal inline "items missing inputs" dot near the export button. It also restores the zone-level "honesty guard" sync-status logic that was partially (and unsafely) removed in the working tree, and removes now-dead requestedFormTab plumbing that existed only to support the modal's click-to-navigate.

1 Executive Summary

What stays. useAutoCalculation (components/dashboard/use-auto-calculation.ts) keeps its core job: watch for HAC-relevant changes via setHacRelevantChangeCallback / setInheritanceCascadeCallback, debounce, build a plan with buildCalculationPlan, POST to /api/bs-calculation/batch, merge results via setStudy. The hook's public surface shrinks from { isPending, isCalculating, failedItems, retryAll } to { isCalculating, failedCount }.

What goes. HacStatusIndicator (icon + badge + tooltip + click-to-open) and CalculationFailureModal (breadcrumbs, error sanitization, retry-all, click-to-navigate) are deleted outright, along with their tests. The requestedFormTab context plumbing that existed solely to let the modal jump to the HAC form tab is removed from layout.tsx, page.tsx, and study-tree-context-provider.tsx.

What's restored. The working tree currently has an incomplete, unsafe removal of the zone-level "honesty guard" in lib/calculation-versioning.ts (and 4 dependent test files). This guard prevents a BS EN 60079-10-1 zone with no dispersionType — which calculates successfully but returns outputs: {} — from showing as a false "in-sync"/green result. Phase 0 reverts these 5 files to their committed HEAD state, restoring the guard. This is unrelated to the indicator/modal removal but must happen on this branch regardless.

8 Edge Cases & Invariants to Preserve

  • failedCount === 0 while isCalculating === true: dot hidden; export button tooltip falls through to the "Calculations in progress — please wait" branch (line 194-195, unchanged).
  • failedCount > 0 and isOutOfSync === true: tooltip priority order at lines 192-200 is preserved — only the failed-items branch's text changes (per Phase 2).
  • Scenario with hac.hacType === "None" or unset: getSyncStatusLabel returns never-calculated (existing/committed logic, untouched) — this must not be counted by isRootCauseFailure/failedCount, matching current failedItems filter behaviour. Preserve the exact filter conditions from the current failedItems useMemo when rewriting as failedCount.
  • Cascading vs root-cause failures: isRootCauseFailure() (filters out engineVersion === "dependency-failure" and known cascade error patterns) must continue to gate failedCount — a cascade failure on a descendant must not inflate the count when its root cause is already counted.
  • Zone with empty outputs (no dispersionType): after Phase 0, zoneHasRealResult() returns false → rollup is never-calculated, not in-sync. This affects isOutOfSync/canExportSafely on the export button — re-verify the export button's disabled/tooltip states still make sense post-revert (they predate this branch's UI changes, so should already be consistent).
  • No study loaded (studyIndex === "root"): isStudyLoaded is false; the header row (and thus any indicator) is not rendered at all — unchanged.
  • Amber dot accessibility: aria-hidden="true" on the dot itself; the export button's existing aria-label="Export report" plus its TooltipContent text (updated in Phase 2) remain the accessible description of state — do not add a second competing label.
  • Icon-only sidebar mode (isIconOnly, controlsWidth <= ICON_ONLY_WIDTH_PX): the export button shrinks to icon-only — confirm the absolutely-positioned dot still renders sensibly (doesn't overflow/clip) at the narrow width.
