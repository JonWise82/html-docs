01 Executive Summary

The current CalculationFailureModal shows a flat list of failed item names, raw type enum strings, and raw internal error messages. Users cannot tell where in the study hierarchy a failed item sits, cannot navigate directly to it, and see confusing messages like "Equipment item outputs are undefined."

This plan delivers three targeted improvements with no schema migration and no breaking API changes:

1. Breadcrumb path — Each row gains a compact ancestor trail (e.g., Facility > Area > Compressor) computed from the existing getAncestorItems traversal utility, with the study root excluded and names truncated at 15 characters.

2. Clickable navigation — Each row becomes a button. Clicking selects the item in the study tree via the existing dataProvider.onSelectItems hook (which already handles ancestor expansion and scroll-into-view) and closes the modal.

3. User-friendly errors with visual distinction — A sanitizer in the modal maps internal messages to plain English. Amber text flags dependency errors ("fix a parent first"); red text flags input validation errors ("fix this item's inputs"). Type badges are formatted via the existing formatHierarchyAsName utility.

The failed-items list is also sorted hierarchically (parents before children) by replacing the arbitrary Object.values() scan with a depth-first traversal from the study root.

DFS Traversal Logic (hierarchical ordering)

ℹ
Why DFS instead of Object.values()? Object.values() iterates in insertion order, which is arbitrary. A DFS from the study root using the children[] arrays on each item gives a guaranteed pre-order traversal: every parent appears before its children. This is important when both an Area and its child Scenario have failed — the Area (the root cause) appears first.
flowchart LR START(["studyIndex"]) --> S1["stack = [studyIndex]\nvisited = {}"] S1 --> LOOP{stack empty?} LOOP -->|no| POP["index = stack.pop()"] POP --> VIS{visited?} VIS -->|yes| LOOP VIS -->|no| MARK["mark visited\nitem = studyItems[index]"] MARK --> FAIL{calculationState\n=== 'failed'?} FAIL -->|yes| ADD["compute breadcrumb\npush to result"] FAIL -->|no| PUSH ADD --> PUSH["push children\n(reversed) onto stack"] PUSH --> LOOP LOOP -->|yes| DONE(["return result"])

Breadcrumb Computation

flowchart LR A["getAncestorItems\n(index, studyItems)"] --> B["[parent, grandparent,\n..., study-root]\nbottom-to-top"] B --> C[".reverse()\ntop-to-bottom"] C --> D[".slice(1)\ndrop study-root"] D --> E[".map(a => name ?? index)\nstrings only"] E --> F["truncateCrumb\n15 chars + …"] F --> G["breadcrumb: string[]"]

A2 — Rewritten failedItems useMemo

use-auto-calculation.ts
const failedItems = useMemo(() => {
  const studyIndex = dataProvider.getStudyIndex();
  if (studyIndex === "root") return [];

  const { studyItems } = dataProvider;
  const result: FailedItemInfo[] = [];
  const visited = new Set<string>();
  const stack: string[] = [studyIndex];

  while (stack.length > 0) {
    const index = stack.pop()!;
    if (visited.has(index)) continue;
    visited.add(index);

    const item = studyItems[index];
    if (!item) continue;

    if (item.calculationState?.status === "failed") {
      const info = item.information as { name?: string } | undefined;
      const ancestors = getAncestorItems(index, studyItems);
      const breadcrumb = [...ancestors]
        .reverse()          // bottom-to-top → top-to-bottom
        .slice(1)            // drop study root (first item after reverse)
        .map((a) => (a.information as { name?: string } | undefined)?.name ?? a.index);

      result.push({
        index,
        name: info?.name ?? index,
        type: item.type,
        errorMessage: item.calculationState.error?.message ?? "Unknown error",
        breadcrumb,
      });
    }

    if (item.children) {
      for (let i = item.children.length - 1; i >= 0; i--) {
        const child = item.children[i];
        if (child && !visited.has(child)) stack.push(child);
      }
    }
  }

  return result;
}, [dataProvider.studyItems]);

interface Props {
  open: boolean;
  onClose: () => void;
  failedItems: FailedItemInfo[];

}

export function CalculationFailureModal({ open, onClose, failedItems, onNavigateToItem }: Props) {
  return (
    <Dialog open={open} onOpenChange={(isOpen) => { if (!isOpen) onClose(); }}>
      <DialogContent className="max-w-lg">
        <DialogHeader>
          <DialogTitle>Calculation Failures</DialogTitle>
          <DialogDescription>
            {failedItems.length} item{failedItems.length === 1 ? "" : "s"} failed to calculate.
            Correct the inputs below and results will update automatically.
          </DialogDescription>
        </DialogHeader>
        <div className="flex flex-col gap-2 max-h-96 overflow-y-auto">
          {failedItems.map((item) => {
            const { message, category } = sanitizeError(item.errorMessage);
            return (
              <button
                key={item.index}
                type="button"
                onClick={() => onNavigateToItem(item.index)}
                className="rounded-md border p-3 text-sm text-left w-full hover:bg-muted/50 transition-colors focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-ring"
              >
                {item.breadcrumb.length > 0 && (
                  <div className="flex items-center flex-wrap gap-0.5 mb-1 text-xs text-muted-foreground">
                    {item.breadcrumb.map((crumb, i) => (
                      <span key={i} className="flex items-center gap-0.5">
                        {i > 0 && <ChevronRight className="h-3 w-3 shrink-0" />}
                        <span title={crumb}>{truncateCrumb(crumb)}</span>
                      </span>
                    ))}
                  </div>
                )}
                <div className="flex items-center gap-2 mb-1">
                  <span className="font-semibold">{item.name}</span>
                  <span className="text-xs text-muted-foreground bg-muted px-1.5 py-0.5 rounded">
                    {formatHierarchyAsName(item.type)}
                  </span>
                </div>
                <p className={category === "dependency" ? "text-amber-500 text-xs" : "text-destructive text-xs"}>
                  {message}
                </p>
              </button>
            );
          })}
        </div>
      </DialogContent>
    </Dialog>
  );
}

09 Risks & Mitigations

RiskLevelMitigation
New error message from BS engine doesn't match any sanitizer pattern — shows raw internal text LOW Default passthrough returns raw message as-is (no crash). New patterns can be added incrementally as discovered.
DFS traversal over large study tree causes useMemo to be noticeably slow LOW useMemo only re-runs when studyItems changes. DFS is O(n) on number of items. Studies are typically small (tens to low hundreds of items). The existing Object.values() scan was already O(n).
onNavigateToItem is now a required prop — any future use of the modal without it breaks compilation LOW Only one usage site (hac-status-indicator.tsx). Typecheck catches missing prop immediately. If a second call site is ever added, the prop must be provided.
Breadcrumb truncation at 15 chars may cut through the middle of meaningful words LOW Full name is available on hover via title={crumb}. Users can see the full crumb by hovering. Truncation limit is a UX trade-off already agreed.
Calling dataProvider.onSelectItems from the modal could theoretically trigger a HAC re-calculation if the newly selected item has stale results LOW Selection changes do not trigger HAC calculations. Only HAC-relevant input changes (via hacRelevantChangeCallback) trigger debounced re-calculation. Navigation is read-only.
