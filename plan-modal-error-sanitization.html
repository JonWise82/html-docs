Modal Error Sanitization

Split each error into a short red label + grey action hint, and guarantee no camelCase variable names or internal identifiers ever reach the UI in the Calculation Failure Modal.

⚡ Executive Summary

The CalculationFailureModal currently renders a single red text line per failed item. This line can expose internal camelCase variable names (e.g. sourceAirVelocity, ambientTemperature) from Zod validation errors, and raw exception strings from unhandled paths via a return raw fallback. A previous cleanup commit removed dead dependency-category branches; this plan completes the job by:

  • ✓ Splitting the single message into a short red label + a grey action hint on a second line
  • ✓ Stripping all Zod field names, ValidationError messages, and item indices before display
  • ✓ Replacing return raw with a safe generic fallback so nothing unexpected leaks
  • ✓ Removing the dead unsupported* branches (they now fall through to the generic fallback)
  • ✓ Adding a full test file covering all 18 sanitization and UI cases

All changes are confined to calculation-failure-modal.tsx and its new test file. The API route, calculation engine, and use-auto-calculation.ts are untouched.

function sanitizeError(raw: string): { label: string; hint: string } {
const STANDARD_HINT = "Click to open and review the inputs.";
const SERVER_HINT = "Try re-running the calculation.";
const GENERIC_HINT = "Try re-running or check inputs.";
if (/missing or invalid inputs:/i.test(raw))
return { label: "Some required fields are incomplete", hint: STANDARD_HINT };
if (/invalid .+ for item .+:/i.test(raw))
return { label: "A field value is out of valid range", hint: STANDARD_HINT };
if (/(temperature|pressure|density|length) must/i.test(raw))
return { label: "A field value is out of valid range", hint: STANDARD_HINT };
if (/one or more required area hac properties/i.test(raw))
return "One or more required area properties are missing — check area inputs.";
return { label: "Missing required area properties", hint: STANDARD_HINT };
// ... (all patterns updated to return { label, hint })
if (/unsupported hactype/i.test(raw))
return "Unsupported calculation type — please contact support.";

return "Unsupported ventilation direction — please contact support.";

⚠️ Risks & Edge Cases

LOWFallback for future errors
Any new error thrown by the calculation engine that isn't matched will show the generic fallback. This is intentional and safe — no internals leak. New patterns can be added to sanitizeError as needed.
LOWTruncated Zod field lists
Messages like "Missing or invalid inputs: f1, f2 and 3 more." still match pattern #1 since the regex checks only the prefix. Works correctly.
LOWrun-hac-helpers.ts path
Confirmed to write into the same calculationState.error.message field as the batch API route. Same sanitization path applies.
LOWNo schema / Firestore migration
The raw error strings remain stored in Firestore unchanged. Only the display layer changes. Items recalculate naturally; no migration needed.
LOWPattern ordering
Patterns 1 and 2 are the broadest new additions; placing them first avoids any ambiguity with later patterns. No known overlap with existing patterns.
LOWNo backwards compatibility concerns
sanitizeError is a private, non-exported function. Its return type change has no external consumers.
