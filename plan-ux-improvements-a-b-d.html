UX Improvements: A, B & D

Branch: feat/auto-hac-calculation Date: 2026-05-30 Plan 3 features 7 files affected

Executive Summary

This plan covers three UX improvements to the auto-HAC calculation system introduced in feat/auto-hac-calculation. All three are additive — they do not change existing calculation logic, data schemas, or Firestore persistence.

🕐 A — Last Calculated Timestamp

When the status indicator is in-sync, expand the tooltip to show a live relative timestamp ("last calculated: 2 min ago") derived from the most-recent completedAt across all succeeded calculable items. Updates every 60 s.

🔁 B — Retry Button

Add a "Retry all" button to the CalculationFailureModal footer. Triggers a full-study recalculation (same as load trigger). Modal stays open with live updates; auto-closes when all failures resolve. Also adds an explicit "Close" button.

🌫️ D — Scroll Fade

Apply a CSS mask-image bottom-fade to the failure modal's scrollable list so users can discover there is more content below. Pure CSS — always visible, no JS overhead.

Step 1A — Add formatRelativeTime to lib/utils.ts PARALLEL

Append a new exported utility function after the existing formatDateTime. Takes a timestampMs: number and an optional now = Date.now() (the now parameter makes it fully testable without mocking Date.now()).

export function formatRelativeTime(timestampMs: number, now = Date.now()): string {
  const diffMs = Math.max(0, now - timestampMs);
  const mins = Math.floor(diffMs / 60_000);
  if (mins < 1) return "just now";
  if (mins === 1) return "1 minute ago";
  if (mins < 60) return `${mins} minutes ago`;
  const hours = Math.floor(mins / 60);
  if (hours === 1) return "1 hour ago";
  if (hours < 24) return `${hours} hours ago`;
  const days = Math.floor(hours / 24);
  return days === 1 ? "yesterday" : `${days} days ago`;
}

const lastCalculatedMs = useMemo(() => {
  if (displayState !== "in-sync") return null;
  let mostRecent: number | null = null;
  for (const item of Object.values(studyItems)) {
    if (!isCalculableItemType(item.type)) continue;
    const cs = item.calculationState;
    if (cs?.status !== "succeeded" || !cs.completedAt) continue;
    const t = new Date(cs.completedAt).getTime();
    if (mostRecent === null || t > mostRecent) mostRecent = t;
  }
  return mostRecent;
}, [displayState, studyItems]);

Edge Cases & Risks

MED Auto-close race with navigation

If the user clicks a failed item to navigate while retry is also running, the item resolves during navigation. The auto-close effect fires after failedItems.length drains. Since the modal is already "effectively dismissed" (the navigation closed it via onNavigateToItem → setIsModalOpen(false)), the auto-close effect calling onClose again is a no-op. Safe.

MED Timestamp with future completedAt

formatRelativeTime uses Math.max(0, now - timestampMs) to guard against clock skew yielding a negative diff. Negative diff would show "just now" rather than a confusing negative string.

LOW Ticker memory leak

The setInterval in HacStatusIndicator is cleared in the useEffect cleanup. No leak risk.

LOW Scroll fade on very short lists

The CSS mask is always visible, even when the modal list doesn't overflow. The fade covers ~20% of the list height. Cosmetically acceptable; no functional impact.

LOW isCalculableItemType scope

isCalculableItemType returns true for facility | area | equipmentItem | scenario | zone | ignitionSource. Facilities are rollup containers — they may have a completedAt in older data but it would be valid to include. The status === "succeeded" check filters out any invalid states.

LOW Study switch during ticker

When the user switches studies, studyItems changes, triggering lastCalculatedMs recomputation. The ticker itself is unconditional (doesn't depend on the study), so it keeps ticking — correct behaviour.

LOW Retry on input-error items

If all failures are input-validation errors, clicking "Retry all" will immediately re-fail them. The list updates back to the same state; the modal stays open. The per-item hints ("Click to open and review the inputs") guide the user. Acceptable.

LOW mask-image dark/light mode

mask-image uses alpha channels (black = opaque, transparent = transparent) — not colour values. Works identically in light and dark themes. No theme-specific logic needed.

  • Clicking a failed item in the modal navigates to the item, opens the HAC tab, and closes the modal — unchanged
