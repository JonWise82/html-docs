1. Executive Summary

This branch is a major UI overhaul across the study dashboard. The work bundles several feature sub-branches into one: it removes a redundant "Options" tab, replaces the two-tab sidebar (Study/Settings) with a compact single-row toolbar, introduces a contextual add-bar below the study tree, refactors all study modals to support imperative triggers, consolidates four dedicated banner components into the shared Alert component, and — most importantly — migrates the models and drawings media fields from information to geometry across the Firestore schema.

The change is primarily cosmetic and structural, but the schema migration is a data-compatibility concern that deserves careful review. No server-side calculation logic changes. No authentication changes.

3. Sidebar Redesign

What changed
The sidebar previously had a 2×2 grid of modal-trigger buttons (New / Load / Save / Close) plus a two-tab section (Study Tree | Settings). Both are replaced with a compact single-row toolbar that adapts to narrow widths by going icon-only.
Before
■ 2×2 / 4-col grid of buttons (New, Load, Save, Close)
■ Tabs: [Study Tree] [Settings]
■ Settings: ghost buttons list in a tab panel
■ No study name shown
■ Export Report lived only in study tree context menu
■ Run HAC button not in sidebar toolbar
■ Modals rendered inline, each with their own trigger button
After
■ Study name <h1> shown when loaded
■ Single row toolbar: [File ▾] [💾] [▶ Run HAC] [📥 Export] [⚙️]
■ File = dropdown (New / Load / Save / Close)
■ Settings = dropdown menu (4 configurators)
■ Export button moved into toolbar (with out-of-sync warning toast)
■ Responsive: icon-only at ≤320 px container width
■ Modals hidden by default; triggered imperatively via refs

New sidebar layout structure

Key implementation decisions

  • Export out-of-sync check is now duplicated — both side-bar.tsx and study-tree.tsx compute canExportSafely independently. Not a bug but a coupling risk if the logic diverges.
  • usePanelWidth drives responsive behaviour; the 320 px breakpoint matches the same constant in StudyTreeAddBar.
  • The inline export modal (ExportReportModal) is now also rendered in side-bar.tsx in addition to study-tree.tsx. Two instances are mounted; they are guarded by separate open-state booleans so only one shows at a time, but it's worth noting the duplication.

4. Options Tab Removal & Analysis Tab Redesign

The "Options" (sliders) tab, which contained toggles to enable Risk Assessment / HAC / Geometry, has been completely removed. Those toggles are now embedded as tiny +/× buttons on the tab labels themselves. Disabled analysis tabs are always shown but rendered with a lock icon and are non-clickable.

Review focus: tab slot stability
The old approach used a dynamic availableFormTabs state array that would grow/shrink, causing tab layout reflow. The new getApplicableFormTabs() is computed from the item type at render time (never changes for a given item) and the isTabEnabled() function reads from options at render time. This is cleaner, but verify that disabling a tab while it is the active tab correctly falls back to "information" (the handleDisableTab() callback does set this, but confirm it fires before the tab unmounts).

6. Imperative Modal Handles

What changed
All four study modals (NewStudyModal, LoadStudyModal, SaveStudyModal, CloseStudyModal) were refactored from components that render their own trigger button to components that expose an imperative trigger() handle via forwardRef + useImperativeHandle. A hideButton prop suppresses the internal button when the modal is controlled externally.

Old vs New modal trigger pattern

Review focus
The hideButton prop must be verified in all four modal components to confirm the internal trigger button is correctly suppressed when set. Also verify the modal's internal open-state management is preserved — the ref just calls setIsOpen(true), so the modal still fully controls its own open/close lifecycle.

7. Data Model / Schema Changes

Migration concern
Existing Firestore documents will have information.models / information.drawings. When loaded, Zod will parse the document. Since the old fields are no longer in the schema, Zod's .strip() default will discard any existing models/drawings silently. Existing uploaded 3D models and drawings will disappear on next load until a migration script backfills the data to geometry.*.
